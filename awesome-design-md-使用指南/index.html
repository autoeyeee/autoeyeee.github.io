awesome-design-md 使用指南：84 份设计文档怎么读、怎么用

发表于2026-10-25|更新于2026-10-25|教程设计
|浏览量:

开源 · 设计文档 · 使用指南

84 份 DESIGN.md

怎么读、怎么用，以及别指望它替你画界面

第一次打开 awesome-design-md 容易失望：说好的 84 套设计，怎么全是 Markdown？但把它当成「设计规格书」而不是「UI 素材库」，它立刻就好用了。

这个库到底是什么

一句话：它把 84 个真实网站的设计语言，拆成了可读、可抄、可执行的文字规格。

84份 DESIGN.md
74份带 YAML token
10份只有正文
4.3–44KB / 份

仓库结构很朴素：design-md/<站点>/DESIGN.md，同目录的 README.md 只有两百来字节，是个索引占位。没有图片、没有 HTML、没有 Figma 文件，也没有演示页。

它最像的东西，是一份「视觉验收标准」：设计师看完能复述品牌的样子，工程师看完能写出 token，AI 看完能生成八九不离十的页面。

84 套怎么分类

仓库按行业把 84 份分成了 10 类，数量差得挺大：消费科技最多（16），复古网页只有 2 份。这个分布本身就有用——想找和自己场景相近的参照，先锁定这一类。

分类 数量 代表 适合看什么
Media & Consumer Tech 16 Apple、Spotify、WIRED、The Verge、NVIDIA 大图、强品牌、编辑式排版
AI & LLM Platforms 13 Claude、Cohere、Mistral、Ollama、xAI 暗色科技感、terminal 风、渐变
Backend / Database / DevOps 9 Supabase、Sentry、PostHog、MongoDB 文档型站点、开发者密度
Fintech & Crypto 9 Stripe、Coinbase、Wise、Mastercard 信任感、数据密集、克制的配色
Productivity & SaaS 8 Linear、Notion、Resend、Cal.com 极简、留白、组件细节最全
Developer Tools & IDEs 7 Vercel、Raycast、Cursor、Warp 单色、等宽、键盘优先
Automotive 7 Ferrari、BMW、Tesla、Lamborghini 大幅影像、极简字、强对比
Design & Creative Tools 6 Figma、Framer、Webflow、Miro 图形语言与动效
E-commerce & Retail 6 Airbnb、Nike、Shopify、Starbucks 商品卡、暖色、圆角
Retro Web 2 Dell (1996)、Nintendo (2001) 复古 UI、拟物细节
未归类 1 Slacc 读一下就好

分类来自仓库 README；实际目录里还有 1 套（Slacc）没写进分类表，所以加起来是 84。分类只影响「从哪儿开始翻」，不影响文档本身的质量。

一份文件里有什么

开头是一段 YAML，这是整份文档里最像「代码」的部分，也是最能直接用的一段：

YAML 后面是若干段说明。README 里的规范是 9 段，实际文件常见的是这样：

段落 里面写什么 值不值得读
Overview 氛围、气质、几个 Key Characteristics 先扫一眼
Colors 颜色 + 语义角色（canvas / surface / ink / hairline / accent） 必读
Typography 字族 + 完整层级表（字号 / 字重 / 行高 / 字距） 必读
Layout 间距刻度、栅格、容器宽度、留白理念 选读
Elevation & Depth 阴影与 surface 阶梯 选读
Shapes 圆角刻度、图片比例 必读，圆角就是品牌语言
Components 按钮 / 卡片 / 输入框 / 导航 / 页脚，含三态和具体数值 最有用
Do’s and Don’ts 品牌红线 必读，防止「像但不对」
Responsive / Iteration / Known Gaps 断点、迭代建议、已知缺失 选读

仓库里其实有两种格式：74 份是上面这种「YAML + 英文段落」，另外 10 份（Spotify、Tesla、The Verge、Sanity、Starbucks 等）没有 YAML，是 ## 1. Visual Theme & Atmosphere 到 ## 9. Agent Prompt Guide 的编号正文。后者要靠关键词从正文里找色值，好在它们通常把 hex 写得很规整。

三个例子，差异在哪

Linear

画布 #010102，强调色 #5e6ad2，12px 圆角 + 1px 细线，拒绝投影，层次全靠 surface 阶梯。

WIRED

纯黑白、圆角 0、1px 分隔线，三套衬线分工（显示 / 正文 / 元信息），报头做到 64px。

Claude

纸面 #faf9f5，陶土色 #cc785c，暖灰分隔线 #e6dfd8，衬线标题配人文感正文。

三份文档的 Overview 都是形容词：深邃、克制、温暖。真正能执行的，是上面那些数字和规则。读 DESIGN.md 时，跳过形容词，直接找数字。

怎么读：十分钟读完一份

先看 colors 和 rounded

30 秒建立印象：底色、强调色、中性阶、圆角是 0 还是 12。这四样决定「第一眼像不像」。

跳到 Components，只看三个

按钮、卡片、输入框。抄它们的 padding、圆角、边框和 hover 状态，够用了。

扫 Do's and Don'ts

这里写着「千万别做什么」，比正面描述更省事，也是防止风格跑偏的关键。

看 Typography 的层级表

字号阶、字重、字距是气质的来源；顺手记下它是衬线还是无衬线。

最后再补氛围和 Known Gaps

这两段是给「没看过这家网站的人」的，读几份以后你会发现套路很像。

不要从第一段开始逐字读。84 份文档的 Overview 用的是同一套写法，先读五份就会腻；带着「我要什么」去翻，效率会高很多。

怎么预览：先看，再抄

DESIGN.md 是文字，光读很难判断「这套放到我的页面里长什么样」。按成本从低到高，有三种办法：

办法 成本 能得到什么
翻 getdesign.md 的在线单页 0 色卡与说明，看不到组件组合
自己做一张对照卡 半小时 按钮 / 卡片 / 输入框在真实字号下的样子
用现成的预览页 一条命令 84 套 × 16 个组件，可随时切换

第三种是这个博客里已经搭好的：preview/ 不参与 Hexo 构建，起个本地服务就能看。

画廊：84 张卡，同一组组件套不同的 token；可按分类和深浅筛选

  • 画廊：一张卡一套风格，卡里是同一组组件的迷你版
  • 详情：点进去看 16 个内容组件 + 主题标签 + 一篇样例长文
  • 键盘：/ 搜索、← → 换风格、d 切明暗
  • 复制：右上角「复制 CSS 变量」，选中后直接贴进自己的 :root

详情页：同一套组件换成 WIRED 的 token——直角、衬线、细线，投影全部消失

直接双击 preview/index.html 会被浏览器按 CORS 规则拦掉本地字体和图标，字体会退成系统默认；要看准的，还是用 npm run preview 起本地 http。另外「反相」只是近似深浅，真要深色请用文档里的原生深色值。

三种实际用法

一、丢给 AI

仓库设计的原始用法就是：把某份 DESIGN.md 复制到项目根目录，然后让 AI 按它来做页面。Google 的 Stitch 原生支持这种文件，也可以直接把内容贴进对话。

那 10 份编号正文的文件末尾，有一段 ## 9. Agent Prompt Guide，里面是现成的 prompt。比如 Spotify 那份直接写好了「做一个胶囊按钮：#1f1f1f 背景、白字、9999px 圆角、8×16 内距」。直接抄，比你自己描述准确。

二、抽成项目变量

如果你有自己的主题或组件库，最稳的方式是只取 token，映射成 CSS 变量，然后只改这一层：

两件必须自己补的事：

  • 字体：文档里大多是专有字体（Linear Text、WiredDisplay、StyreneB、SoDoSans），浏览器会 fallback。要么找公开替代（Inter、Lora、思源宋体），要么接受系统字体。
  • 对比度：文档给的是品牌色，正文色不一定过 4.5:1。落到自己站点，用工具重新算一遍再用。

三、当选型参考库

不一定非要抄某一套。做新项目时，先按「想要什么」去翻，往往比在脑内空想快：

想要的感觉 先看这几份
极简暗色、开发者工具 Linear、Vercel、Raycast、Warp
杂志式排版、编辑感 WIRED、The Verge、Sanity
阅读舒服、暖纸面 Notion、Claude、Oura
强品牌色、视觉冲击 Spotify、Nike、Lamborghini
研究圆角语言 WIRED（0）、Notion（4–6）、Linear（8–12）、Spotify（9999）
渐变与光感 Stripe、Framer、Cohere

几个别踩的坑

它是规格，不是界面

文档告诉你「12px 圆角、1px 细线」，不会告诉你页面怎么排。只抄 token，最多拿到六七成气质。

没有预览页

README 说每套带 preview.html，但仓库里实际没有（抽查过）。想「看一眼」只能自己做，或者去 getdesign.md 看单页。

字体和商标不包含

文档是对公开网站视觉的分析，不含品牌字体、logo、图片。商用前先确认字体授权，别直接搬商标。

「看着像」和「用对了」是两件事。仿一个品牌的页面不掉价，但把别人的 logo、插画、专有字体直接搬进自己的产品，性质就不一样了。

一份可以直接照着做的清单

选一个参照，只选一个

一次只对标一套，混搭会变成四不像。

抄 5 个颜色和 1 套圆角

canvas、surface、ink、muted、accent，加上 md/lg 两档圆角。

抄 2 个组件的内距

按钮和卡片。这两个对了，整体就像了。

换字体，算对比度

专有字体换公开替代；正文色重新验一遍 4.5:1。

对照原始站点看差距

把两边截图并排，先看出入最大的地方，别抠细节。

设计文档的价值不是「给你一个皮肤」，而是让你在动手之前，先有一个可执行的判断标准。
