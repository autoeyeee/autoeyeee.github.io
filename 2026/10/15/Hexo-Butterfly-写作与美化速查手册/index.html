Hexo + Butterfly 博客写作与美化速查手册

发表于2026-10-15|更新于2026-10-15|教程Hexo
|浏览量:

这篇是写给我自己的备忘：从「怎么新建一篇文章」到「怎么把界面调顺眼」，把 Hexo + Butterfly 常用的写法、配置和资料链接整理成一份可以长期查阅的速查表。涵盖分类与标签的规范写法、front-matter 全字段、标签插件写法、主题配色与特效配置、可扩展的页面，以及我实际踩过的坑。环境是 Hexo 7.3.0 + Butterfly 5.4.3，站点部署在 GitHub Pages 上。

一、新增一篇文章

1. 基本流程

npx hexo new page "页面名" 建独立页面（关于、留言板这类），npx hexo new draft "标题" 建草稿（草稿要 npx hexo server --drafts 才看得到）。

二、标准写作流程：分类与标签怎么加

写博客最容易偷懒的地方，就是标签和分类随手乱写，写多了以后归档页一团乱。下面是我给自己定的规矩。

0. 一次性准备：建好「分类页」和「标签页」

这两个是独立页面，只需建一次。建好之后，所有文章的分类和标签都会自动汇总到这两个页面里，不需要手工维护列表。

然后确认两个文件的 front-matter 带上了 type（本仓库已经建好了，在 source/categories/index.md 和 source/tags/index.md）：

标签页还能控制排序：

1. 分类和标签的区别（这是关键）

分类 categories 标签 tags
结构 有层级，像文件夹 扁平，平级的关键词
一篇文章能有几个 可以有多个”父级链” 想加几个加几个
写成一个还是一组 写成一个列表，列表顺序 = 层级 写成列表，彼此平级
URL /categories/教程/Hexo/（带层级） /tags/Hexo/

一句话记法：分类回答”这篇属于哪个栏目”，标签回答”这篇讲了什么”。

2. 分类怎么写：列表顺序就是层级

等价于：

不要误解：categories: [教程, Hexo] 不是”同时属于教程和 Hexo 两个分类”，而是”教程 › Hexo”这条层级路径。这一点我实测过（db.json 里 Hexo 的 parent 指向教程），生成出来的 URL 是 /categories/教程/ 和 /categories/教程/Hexo/，/categories/index.html 里会以嵌套列表同时显示两级。

这样会生成 /categories/前端/Vue/ 和 /categories/随笔/，两棵分类树互不干扰。

层级别挖太深：两层（栏目 › 子栏目）对个人博客足够了，三层以上没人点。

3. 标签怎么写

也可以写成一行：tags: [Hexo, Butterfly]。

标签的几条实用规矩（否则越写越乱）：

  1. 一篇文章 2~4 个标签最舒服，超过 5 个基本等于没打。
  2. 复用已有标签，别每次造新词。写之前先扫一眼 /tags/ 页面（或者本地 http://localhost:4000/tags/），能复用就复用。
  3. 别混语言：定了 Hexo 就一直 Hexo，不要一会儿 hexo 一会儿 HEXO，大小写不同会被当成不同标签。
  4. 别把层级信息塞进标签名：Hexo-教程、前端/Vue 这种写法，说明该用分类而不是标签。
  5. 标签名里的空格和中文：能用，但 URL 会被编码（/tags/教程/ 实际是 %E6%95%99%E7%A8%8B），分享出去不好看。在意的话用英文标签。

5. 长期维护：改分类名 / 合并标签

分类和标签没有独立的”管理后台”，它们是从每篇文章的 front-matter 里实时统计出来的。所以：

  • 改名：把 _posts 里所有用了旧名字的文章改掉（VS Code 里 Ctrl+Shift+H 全局替换），然后 npx hexo clean 重建。
  • 合并标签：同上，统一替换成同一个词。
  • 删掉一个分类：把相关文章的 categories 改掉/删掉即可，它自然从 /categories/ 消失。

⚠️ 改完一定要 npx hexo clean。Hexo 的 db.json 会缓存分类和标签，不清理的话旧名字可能还挂在标签页上——我之前就被这个坑过（标签页残留了一条乱码标签，清缓存才消失）。

6. 几个别踩的坑

  • _posts 里 _ 开头的文件会被忽略。我用 __test.md 做实验时文件根本不生成，改名 test-file.md 立刻就出来了。别用下划线开头命名文章。
  • 别在 tags: / categories: 里写标签插件语法，见上文”血泪教训”。
  • 草稿别直接写在 _posts 里：用 npx hexo new draft "标题" 生成到 source/_drafts/，npx hexo server --drafts 可以预览，写完了把文件移到 _posts 再发布。

五、踩过的坑

  1. 改了没生效：先 npx hexo clean。Hexo 有 db.json 缓存，删文章、改图片名之后最容易踩。
  2. 图片 404：/img/xxx 必须真的存在于 source/img/（或主题的 source/img/）。建议一律放根目录 source/img/，因为主题升级会覆盖主题自己的 source 文件夹。
  3. front-matter 里写了标签插件语法：见上文，会把标签名污染成一整行乱码。
  4. PowerShell 里用 && 连接命令：老版本会报错，用 ; 或分两行。
  5. deploy 报 dubious ownership：文件夹属于另一个 Windows 账户时 Git 会拒绝操作，按报错提示执行 git config --global --add safe.directory D:/blog/.deploy_git 即可。
  6. deploy 报认证失败：需要 GitHub 凭据（SSH key 或 Personal Access Token），不是权限问题。
  7. 部署是 --force 推送：线上仓库会被替换成 public/ 的样子。若往 Pages 仓库手动放过文件（比如 CNAME），一定要放进 source/。
  8. 版本差异：本文写于 Butterfly 5.4.3，官方已更新到 5.7.0。升级前务必备份 themes/butterfly/source/img/；另外 5.6 起主题移除了内置 APlayer/Meting 音乐播放器，要加音乐页需走替代方案。
